## Summary

Publish the repository's public SSH signer registry and enforce trusted SSH
signatures for new commits and annotated release tags in CI. The validators
read trust files from the trusted parent revision, preventing a change from
adding a signer and authorizing itself. A base-controlled pull_request_target
job protects the PR signature check from workflow changes in the PR itself.

## Motivation

Make repository and release provenance auditable while keeping the encrypted
private signing key, passphrase, and SSH agent socket off-repository. A static
parent baseline also makes signer rotation explicit: add a key in one push,
then use it in a later push. The trusted PR job keeps the signature gate tied
to the base revision rather than untrusted workflow code.

## Test Evidence

The bootstrap and enforcement commits have SSH signatures from the registered
key. make check, scripts/test/test_signatures.sh, all policy/quality/
supply-chain/action-pinning/repository-shape validators, bash -n, and
git diff --check passed. The fixture covers valid, diverged, unsigned,
revoked, self-authorizing signer, annotated-tag, and lightweight-tag cases. The
remote bootstrap and enforcement workflows passed on GitHub Actions. No
private material is tracked.

## Risk

An incorrect signer registry can reject valid work or trust the wrong key. CI
depends on complete Git history and a protected base workflow; branch
protection must require both ugs-validate and ugs-signatures. Signer rotation
must be reviewed as a security-sensitive change and completed before dependent
work uses the new key.

## Rollback

Revert the enforcement and signer-registry commits, or revoke a compromised
key by adding it to keys/revoked_signers. No private key material is created or
removed by this change.

## Breaking Change

New commits in validated ranges and release tags require trusted SSH
signatures. Existing unsigned history and the pre-enforcement v0.0.1 tag are
not rewritten; enforcement starts from the trusted baseline.
