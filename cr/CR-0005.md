## Summary

Add a QEMU BIOS and UEFI boot smoke test to the ISO build workflow, provide
live-console auto-login configuration, and document CI as the authoritative
verification environment for project changes.

## Motivation

Checksum validation proves artifact integrity but does not prove that the ISO
boots into a usable live environment. The project also needs a consistent
record of CI evidence rather than treating workstation builds as release
verification.

## Test Evidence

Local make check, policy validators, shell and Python syntax checks, and
git diff --check pass. The local ISO build could not complete because the
Arch package mirror timed out, and this host lacks QEMU, OVMF, and Tesseract;
these local limitations are diagnostic only.

## Risk

The boot smoke test depends on QEMU, OVMF, Tesseract OCR, and the Archiso live
console reaching the expected prompt. OCR or upstream firmware changes could
produce a false failure; a missing boot path should fail the build before an
artifact is uploaded.

## Rollback

Revert the signed commit and remove the CI boot smoke-test step and live
console files. Existing checksum-only artifact verification remains available
through the prior workflow revision.

## Breaking Change

Build workflow runs take longer and require QEMU, OVMF, and Tesseract on the
GitHub runner. No CLI selector or artifact naming contract changes.

## Backport Target

None.
